# OAIP Battles

Автоматический баттл-дашборд для учебных задач на C++.

- **5 команд** сдают по одному решению.
- **Команды пишут тесты друг для друга** в неограниченном количестве.
- **Преподаватель** создаёт ветку `vs/A-B` в веб-интерфейсе GitHub — CI сам собирает, тестирует и сравнивает решения.
- **Дашборд** показывает текущий баттл, провалы с `input`/`actual`/`expected`/`diff`, краш-матрицу и историю.

Дашборд: https://study-dump.github.io/OAIP-Battles-IEF/

Устанавливать ничего не нужно: весь запуск — создание ветки и коммит в браузере.

---

## Структура

```
teams/teamN/solution.cpp                 решение команды N
tests/teamN/0X_описание/                 тест команды X против команды N
    input.txt
    expected_output.txt
scripts/compare.py                       сравнение с допуском на double
scripts/runner.py                        прогон тестов одной команды
scripts/merge_results.py                 определение победителя + JSON
site/                                    статический дашборд (GitHub Pages)
.github/workflows/                       battle / deploy-pages / clear-history
```

### Правило имён тестов

- `tests/teamN/` — **кого атакуют** (N — номер защищающейся команды).
- `0X_описание/` — **кто атакует** (`0X` — номер команды-автора, двузначный).

Пример: `tests/team1/04_dup_article/` — team4 атакует team1.

Нельзя атаковать свою команду: `tests/teamN/0N_*` игнорируется runner-ом.

## Командам

### Решение

Положите решение в `teams/teamN/solution.cpp`. Один файл на команду, без доп. файлов и библиотек.

Контракт запуска:

- CI компилирует `g++ -O2 -std=c++17 solution.cpp` на Ubuntu.
- Решение запускается в пустом временном каталоге, куда кладётся `input.txt`.
- Содержимое `input.txt` **также подаётся на stdin**.
- Ответ берётся из `output.txt` в текущем каталоге. Если файл не создан — из `stdout`.
- Если созданы оба, приоритет у `output.txt`.

Шаблон с нужным I/O уже лежит в `teams/teamN/solution.cpp` — замените его своим кодом.

### Тесты

Для теста нужны два файла:

```
tests/teamM/0N_short_name/input.txt
tests/teamM/0N_short_name/expected_output.txt
```

- `teamM` — команда, которую атакуют.
- `0N` — команда-автор теста (например, `04`).
- Тесты маленькие: 5–20 записей, без нагрузочных проверок.
- Формат `expected_output.txt` фиксирован условием задачи. Сравнение построчное, числа — с абсолютным допуском `1e-6`, пробелы и `\r` нормализуются.
- Все тесты публичны: скрытых тестов организатора нет.

Лимиты: 5 секунд на один тест, 15 минут на весь баттл.

## Преподавателю: запуск баттла

1. Убедитесь, что свежие решения и тесты уже в `main`.
2. Откройте репозиторий на GitHub в браузере.
3. Создайте ветку с именем **ровно** `vs/A-B`, где `A` и `B` — разные номера команд от 1 до 5 (например, `vs/1-4`).
4. В этой ветке измените любой файл (например, добавьте строку в `README.md`) и сделайте коммит.
5. Всё. Запустится `Battle`:
   - компилирует оба `solution.cpp`;
   - прогоняет `tests/teamA/0B_*` против teamA и `tests/teamB/0A_*` против teamB;
   - определяет победителя;
   - коммитит `site/results.json` и `site/history.json` в `main`;
   - обновляет GitHub Pages.

Ветку `vs/A-B` можно удалить после баттла.

В `main` из ветки попадают **только** файлы `site/results.json` и `site/history.json`; остальные изменения ветки не переносятся. Поэтому решения и тесты должны быть в `main` до создания ветки.

### Как определяется победитель

1. Больше доля пройденных тестов (`passed / total`).
2. При равенстве — меньше среднее время.
3. Если тестов от соперника нет (`0/0`), команда получает `0` и, как правило, проигрывает. При `0/0` у обеих — ничья.

Время на раннере шумит и используется только как тай-брейк; жёсткий лимит — 5 секунд на тест.

## Локальный запуск

Нужны `g++` с C++17 и Python 3.8+.

```bash
g++ -O2 -std=c++17 teams/team1/solution.cpp -o /tmp/sol1
g++ -O2 -std=c++17 teams/team2/solution.cpp -o /tmp/sol2

python3 scripts/runner.py \
  --solution /tmp/sol1 --tests-dir tests/team1 \
  --author-prefix 02 --team 1 --opponent 2 --out /tmp/partial_a.json

python3 scripts/runner.py \
  --solution /tmp/sol2 --tests-dir tests/team2 \
  --author-prefix 01 --team 2 --opponent 1 --out /tmp/partial_b.json

python3 scripts/merge_results.py \
  --a /tmp/partial_a.json --b /tmp/partial_b.json \
  --battle vs/1-2 --out site/results.json

python3 -m http.server 8000 -d site
```

`merge_results.py` перезаписывает `site/results.json` и дописывает `site/history.json`.
Вернуть исходное состояние: `git checkout -- site/`.

Проверка модуля сравнения:

```bash
python3 scripts/compare.py
```

## Дашборд

Вкладки:

- **Баттл** — счёт команд, среднее время, все провалы с `input`/`actual`/`expected`/`diff` и `stderr`.
- **Краш-матрица** — агрегат по истории: строка защищается, столбец атакует.
- **История** — все баттлы с победителем и счётом.

Кнопка **«Очистить историю»** открывает workflow `Clear History` в GitHub Actions. Нажмите там **Run workflow** — `site/results.json` и `site/history.json` сбросятся, Pages обновится автоматически.

---

## Ветки и workflows

| Workflow | Триггер | Что делает |
|---|---|---|
| `Battle` | push в `vs/*` | собирает, тестирует, пишет результаты в `main` |
| `Deploy Pages` | push в `main`, завершение `Battle` / `Clear History` | публикует `site/` на Pages |
| `Clear History` | ручной `workflow_dispatch` | сбрасывает JSON |

В настройках репозитория Pages должен быть включён с источником **GitHub Actions**
(Settings → Pages → Build and deployment → Source: GitHub Actions).

## Ограничения

- Репозиторий публичный: решения и тесты видны всем.
- Нет скрытых тестов и официального жюри — только взаимные атаки.
- Нет памяти/песочницы: компиляция и запуск на стандартном Ubuntu-раннере.
- История и тела провалов обрезаются до 5000 символов на поле.
- Время раннера нестабильно; оно не является строгим критерием, кроме тай-брейка.
